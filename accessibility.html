Accessibility Statement for https://breezy.inf.ed.ac.uk (LM Playschool Annotation Tool)

This website is run by the School of Informatics. It is a research annotation tool: it shows participants transcripts of AI models playing simple games and asks them to rate the quality of each move. Participants reach it through a Prolific study link and work through five screens in a single sitting — a welcome page, a consent form, a short practice round, the main annotation screen and a final overall verdict.

We want as many people as possible to be able to use this website. For example, that means you should be able to:

  • navigate the whole study using just a keyboard and see clearly which control you are on
  • move between the turns of a transcript using the arrow keys
  • use a screen reader for the transcript and for every rating question, each one is announced with the question it belongs to and the turn it is on
  • hear an announcement when a screen changes, when your work is saved and when a question is missing
  • be taken straight to the unanswered question if the app refuses to submit
  • leave the consent form without agreeing to take part
  • read the text at the size your browser is set to

We have not been able to make the following work, and you should not expect them to:

  • changing colours or contrast levels, the app forces a dark theme and overrides your browser and operating-system colour settings
  • zooming in without content spilling sideways off the screen or using the app on a narrow screen such as a phone
  • understanding the Wordle colour tiles or the map diagrams without sight, their meaning is carried by colour only

AbilityNet has advice on making your device easier to use if you have a disability. The University also provides a page on how to alter your browser to improve the accessibility of web pages — www.ed.ac.uk/about/website/accessibility/customising-site

How accessible this website is

We know these parts of this website are not fully accessible:

  • The app forces itself into dark mode and cannot be switched to a light or high-contrast theme.
  • The pages do not reflow at high zoom or on narrow screens, so you may have to scroll horizontally as well as vertically.
  • In the Wordle game, the coloured letter tiles that tell you whether a letter was correct carry that meaning in colour alone. The same applies to the map diagrams in the map-based games: they are labelled as maps, but the label does not describe what the map shows.
  • The board layouts in some games are drawn with text characters, which a screen reader will read out character by character.

Technical information about this website's accessibility

The University of Edinburgh is committed to making its website accessible, in accordance with the Public Sector Bodies (Websites and Mobile Applications) (No. 2) Accessibility Regulations 2018.

Compliance status

This website is partially compliant with the Web Content Accessibility Guidelines version 2.1 AA standard, due to the non-compliances listed below.

Non-accessible content

The following items do not comply with the WCAG 2.1 AA success criteria. Each one names the screens it affects.

Colours and contrast cannot be changed

Affects: all screens.

On load, the app rewrites its own URL to force the dark theme and reloads. There is no control to return to a light theme, and the forced theme overrides the browser or operating-system colour preference. This is a constrained choice, not a preference: the custom visual representations we built for some games, to make them easier to annotate, did not render correctly under Gradio's light theme, so the app needed to be locked to a single theme; we chose dark for reduced eye strain across long reading sessions. Users who need a light background or a high-contrast palette cannot get one. This is a barrier under 1.4.3 Contrast (Minimum) for those users and it removes the customisation route that the University's own accessibility advice points people to.

All text throughout the app now meets the 4.5:1 minimum against the dark theme it forces. The problem is the absence of choice, not the palette itself.

The pages do not reflow when zoomed

Affects: all screens.

The stylesheet contains no responsive breakpoints. The top navigation bar and the main two-column annotation area are both set never to wrap, several columns have fixed pixel widths, and the transcript panel is given a fixed pixel height by a script. At normal zoom on a standard laptop screen, the layout displays correctly. But at 400% zoom — a common accommodation for low vision — or on a narrow window, content is cut off or requires scrolling in two directions. This fails 1.4.10 Reflow. Related, all font sizes are set in pixels rather than relative units, so the app does not respond to a browser's own minimum-font-size setting (1.4.4 Resize Text).

Game feedback is conveyed by colour alone

Affects: annotation screen and practice round, for some games.

In the Wordle game the transcript shows each guessed letter on a coloured tile — green, yellow or grey — and that colour is the whole of the feedback. The underlying record does contain the colour as a word, but the display replaces it with a background colour, so a screen reader announces only the bare letters. In the map-based games, the diagrams carry role="img" and a label saying what the diagram is, but the label does not describe what it shows, and correct-versus-incorrect claims are distinguished by ring colour. Since judging exactly this feedback is the task participants are asked to perform, we treat this as a substantive failure of 1.1.1 Non-text Content and 1.4.1 Use of Color.

Board layouts are drawn as text characters

Affects: annotation screen, for grid-based games.

Some games show their board as an ASCII grid. The structure is visual only, so a screen reader reads the border and cell characters one by one. There is no summary alternative. This fails 1.1.1 Non-text Content.

Content that's not within the scope of the accessibility regulations

The transcripts shown for annotation are machine-generated records of language models playing games. They are reproduced verbatim, because altering them would invalidate the ratings participants are asked to give. Their wording, structure and length are therefore not under our editorial control. The surrounding interface — headings, controls, and the questions asked about each transcript — is in scope and is covered by this statement. Note that the colour-only game feedback described above is not claimed under this exemption: the information exists as text in the source record and is lost by our own rendering, so it is our responsibility to fix.

What we are doing to improve accessibility

A first round of fixes has already been completed. We're prioritising the issues that stop people understanding the content itself — the colour-only feedback in Wordle, the map diagrams, and the ASCII board grids — before moving on to navigation (a skip link and landmark regions) and layout (pages reflowing at high zoom, relative font sizes). We're also deciding whether the forced dark theme can be replaced with one that respects a user's own colour settings. We re-test after each round of fixes, update this statement, and check any new screen against this list before it's used in the study.

Preparation of this accessibility statement

This statement was prepared on 19 August 2026. It was last reviewed on 19 August 2026.

This website was last tested on 19 August 2026. The test was carried out by our own research staff.

How we chose what to test

We tested every screen in the application rather than a sample. The study is a single linear task with five screens — welcome, consent, practice round, annotation, and overall verdict — and every participant passes through all five in each session, so there is no page that only a minority of users see. The welcome page is the front page and the annotation screen is where participants spend most of their time; both were examined in the most detail.

Within the annotation screen we checked the shared interface, which is generated by the same code for every game, and separately reviewed how the transcript itself is rendered for each of the 8 games used in the study — which is how the Wordle and map problems described above were found.

How we tested

  • Inspected the stylesheet and generated markup.
  • Calculated contrast ratios for every text/background pair.
  • Ran automated browser checks through a full session: control names, consent dialogue behaviour, screen-change and error announcements, keyboard focus indicators, heading structure.
